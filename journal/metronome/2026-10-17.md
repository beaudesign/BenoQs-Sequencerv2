### What I found

- **CV-4 is "to within a tick", not strict.** Integer rounding makes 18 of the table's cells have two neighbouring gaps that swap by one tick against the sign of the warp (for example gaps 1, 0, 1, 0 for a span of 2 at a negative warp). The test asserts the direction to within one tick, and says so. A strict monotone gap sequence is not possible on a span of a few ticks. The spec's CV-4 text should say "to within a tick"; the Conductor's call.
- **CV-8 was too tight as I first wrote it.** The spec says the heavy scenes stay inside the queue. At strum 9, Bounce peaks at 650 of 1024 slots (Accel 630, Even 550, Manual 490), because the notes are held back toward the end of the span and more are in flight at once. At strum 5 (the heavy scene the existing tests use) every style stays under half (the worst is 450). So: strum 5 keeps the half bound in all styles; strum 9 is bounded at three quarters, with no overflow, nothing deferred and nothing late; the dense overload scene checks nothing is late and every on has its off. This is a measurement, and it is more than the Octopus does, not less.
- **The random stream is exact to test.** `next_random_for_test` peeks the generator, so CV-7 is "an engine with the style and one without have drawn the same count", not a statistical guess.

## Review follow-up (WENGE-0036): three tests that were missing

The owner asked for the work to be tested and evaluated. An independent reviewer mutated the engine in two places and every
test still passed, so I added the three tests below and checked each fails on its mutant (engine restored and diff-checked each time).

- `the_roll_is_spaced_for_the_notes_that_sound_not_for_the_chord_size`: chord sizes 2 to 7 against polyphony 1 to size+4, six seeds,
  six styles. A polyphony below the size draws exactly that many notes; above it, some draws land on a rest, and the roll is the table
  row for the notes that sound (one sounding note is a roll of seven; no note sounding is silence). It also asserts that a draw did land
  on a rest, so it cannot pass by not testing the case it names. Fails when the roll uses the chord size.
- `every_track_plays_in_its_own_style`: ten tracks, each in a different style (five or more distinct tables), told apart by a band of
  pitch because all ten share one port and channel by default. Fails when every track reads track 0's style.
- `a_chain_plays_in_its_heads_style`: a chained member is driven by its head, so the head's style is the chain's and a style set on a
  member does nothing. This pins what the code already did (a chosen reading, consistent with the head owning the cursor).

Also from the review, not changed here: CV-4 holds to within one tick, which SPEC-0005 now says; and the page cannot enter a chord or a
strum, so the Curve button is silent on the page (the owner's call; a way to strum on the page is a new slice).

**A trap I fell into:** two agents building in one `CARGO_TARGET_DIR` can hand each other a stale binary. My first run of the new
tests failed with the roll spaced for the chord size although `engine.rs` was byte-identical to the commit; a rebuild (after `touch`)
passed. The reviewer's mutant build had been left in the shared target directory. Use one target directory per agent, and `touch` a
source file after any restore.
