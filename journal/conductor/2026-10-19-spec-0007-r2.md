## What I found

- **The engine already sends step-locked control change** (a track's MCC target and a step's `mcc_value`), but the page cannot write one. So "the
  sequencer moves the knobs" is blocked by something outside this spec; "the sequence tunes the resonator" and "the loop follows the beat" are not.
- **The engine's clock records exist only while it is clock master.** The click already derives its beats from the tick position, so the pedals' clock can
  be derived the same way and keep working with the outgoing clock off.
- **r1's reorder crossfade cannot work** with stateful pedals (the same instance would run in two orders in one block). Proposed: duck, swap, unduck.
- The monitor adds into the output after the click; the board needs the voices alone, so P0a must put the monitor on its own bus.
- `decodeEvents` allocates each block, so the worklet is not allocation-free today.
- The WENGE-0036 clash: r1's file says it, `handoffs/WENGE-0036.ndjson` (my Curve tests) has it. #76's title on GitHub already reads WENGE-0037.
- r1's README still said "nothing has been pushed" and called #70 open.
