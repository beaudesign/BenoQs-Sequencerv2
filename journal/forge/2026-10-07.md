### What I learned

- A browser's autoplay policy is the whole reason the page cannot show a running pattern before the first press. The test uses Chromium's *default* policy (no `--autoplay-policy` flag) on purpose, so the test fails where the owner's browser would.
- The earlier browser tests drove `Start`, then the engine. Their world is now `?bare` (a hook read only in `pages/app.ts`): nothing loaded, nothing heard. Changing them to the new page would have changed what they test.
- `step_index` in a snapshot had two readers (the playhead drawing and the `link::e2` test); the second assumed "not 0 means it has played". It now asserts `!= NOT_PLAYING`, which is stricter.

### What surprised me

- A refused-MIDI test still said `/Start/` after I had "fixed" it with a `sed` that matched the source string and not the test's regex. A grep after a sed costs one second.
- The S3 browser test ("follow, from the page's own buttons…") fails about one run in four on timing jitter. It does so on `metronome/d0-tick-length` alone, so it is not from this branch. It passed in the final run (69/69). Not fixed here (Referee's zone).
