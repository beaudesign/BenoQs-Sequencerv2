### What I learned

`Grid` (ten `Bank`s deep) is about 1MB as a plain value type. Constructing it
as a stack temporary overflowed the test harness's thread stack — not a
logic bug, a size-of-type problem. Fixed by heap-backing only the outermost
`banks` array (`Vec<Bank>`); everything below `Bank` stays a fixed-size
`Copy` struct on purpose, because `Page` (~6KB) is what the engine actually
copies once per tick, and that copy needs to stay cheap. This is the one
place this crate isn't `no_std`-clean yet.

Two independent prior implementations (the archived JS and the archived C++
port) agree with each other on the direction-4/5 assignment (4 = biased
random walk, 5 = uniform random) but *disagree* with the new doc's own prose
ordering ("random, brownian" as written implies 4 = random). Went with the
two agreeing prior implementations over the un-cited prose — logged in
AMBIGUITIES.md rather than silently picking one.

Also learned, the hard way, that "one tick" and "one step" are not the same
thing when writing the fixture-DSL `play N step` directive — a step is
`DEFAULT_STEP_TICKS` (12) ticks at the default multiplier, and my first pass
at the runner called the tick function once per "step", which fired nothing.

### What's blocked

Phrases, hyperstep, and step-events are real data models with working
resolution/carry functions but aren't wired into the note-firing path — doing
that correctly needs either the real manual or a real `panel.truth.json`
(neither exists), so guessing at the wiring felt worse than leaving it as an
explicit gap. Six ambiguities logged, all provisional against the archived
priors rather than a manual citation. `docs/03-sequencer-core.md` §1's
per-constant `Ref:` citation requirement genuinely cannot be met yet — this
blocks getting past ~20 conformance fixtures (target is ≥250 by Phase 3) no
matter how much more of this crate gets built, until someone supplies
`reference/manual/`.
