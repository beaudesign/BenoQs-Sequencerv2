## 2026-09-29

**Intend to change:** Make `just verify` mean something: a tri-state runner that writes
the report JSON the schema already defines, and a ratchet that fails when a test is
deleted.
**How I'll know it worked:** on a tree with the baseline, deleting any one test makes
`cargo xtask verify` exit 1 naming that test; editing the baseline to hide it is caught
by `--base`; a required gate that is not built exits 1; a clean tree exits 0; the report
validates against `contracts/verification.report.schema.json` in a test.

### What I built (`xtask/`, `harness/`)

- `cargo_out.rs` parses `cargo test` output by test name and cross-checks each binary
  against cargo's own summary line, so a parser miss is loud.
- `baseline.rs` is the ratchet floor (`harness/baseline.txt`) and the diff against a base
  ref. `gates.rs` evaluates `conformance` and `regressions`. The other 12 gates report
  `not_implemented`.
- `report.rs` writes `verification.report/1` with no runtime dependencies.
  `jsonschema` is a dev-dependency used only to prove it validates.

### Decisions I made that the owner may want to reverse

- Unit test results are reported under `regressions`, because the schema has no unit
  gate and adding an enum value is a contract change (ADR needed).
- One assertion is one passing test or one fixture. A proxy. See `harness/README.md`.
- 100 lockfile entries for `jsonschema` (dev only). A hand-written validator would avoid
  them but would validate less. Recorded in ADR-0005.
