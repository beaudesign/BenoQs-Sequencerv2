**Intend to change:** Write SPEC-0002 as a draft for the owner: a product and tech spec for a

### Context

The owner's directive (2026-09-30, 12:58 Paris, recorded in the spec README): the three sources
(v5.30 release notes, v5.30 reference manual, the "basic navigation" blog post) are the main
feature and UI direction; a world-model project slipped into the repo; remove it; keep the
product a web app that runs the sequencer with live MIDI and external instruments and is also
available on Ableton. Before that, the owner asked to plan the UI, and my first pass found six
contradictions in the WENGE documents (sent as a chat message). The new directive replaces that
plan, so it is not a deliverable.

Roles worn, in sequence: Conductor (this entry), Referee (the scope gate spec only), Scribe
(the index request). No code was touched.

### What I found

- **The product was never specified.** The old documents put their detail into rendering and
  rooms. The manual's interaction model (about 140 workflows across the two digests) exists
  nowhere in code: the engine ignores button and encoder commands and never writes an LED. The
  new spec's largest piece is a panel controller, not a renderer (F1).
- **The photography blocker is a native-renderer blocker.** A web panel needs a control
  inventory, and the manual gives one (F2).
- **The WebAssembly path already exists** in CI (F3). The engine's determinism travels.
- **MIDI is output only** (F4, by code search). Clock, input, program change and control maps
  are all missing.
- **"World model" meant two things** (F6). The factory's shared state keeps its name.
- **The manual index is wrong** for the MIDI chapter and after (F5). Request to the Scribe.

### What surprised me

- The factory's own shared-state name is the same as the thing the owner wants removed. A
  grep for it would have deleted `STATE.md`. The scope gate's banned list was written to avoid
  that and the plan says so in section 1.
- The manual is silent on gesture timing and LED animation. A faithful interface needs a
  person with hardware, and the spec says so instead of choosing a number.
- The `loom` hits in a naive search are the concurrency checker, not the Loom role.

### What I got wrong on the way

- A search with `\|` in a multi-alternative pattern matched a literal pipe and returned false
  zeros. I redid it with `|` and checked one known hit.
- I first wrote "about 40" conflicts in the manual. The digests list 36; the table in
  `findings.md` has 20 rows, some combined. I also first filled the "what the spec assumes"
  column with guesses where the manual is silent; those are now `pending` fixtures with no
  assumption.
- The release notes and the blog were read through a summarising tool. That is a limit of this
  draft, not a fact about the sources, and it is written at the top of `findings.md`.

### Blocked or open

- Hardware questions (`tech.md` section 9).
- D0, the tick length (`WENGE-0012`), which the MIDI-clock design now depends on.
- ADR-0006 is not written; it is the first thing after approval (P0).
